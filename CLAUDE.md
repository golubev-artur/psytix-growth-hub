# Psytix — psytix.ru

Платформа курсов по психологии и продажам. Общий контекст (автоматизация, cron, Telegram) — в `~/sites/CLAUDE.md`, он подхватывается автоматически. Здесь только специфика проекта.

- **Репозиторий:** `golubev-artur/psytix-growth-hub` (SSH)
- **Домен:** psytix.ru (GitHub Pages, `public/CNAME`)
- **Стек:** Vite + React 18 + TS + Tailwind + shadcn/ui, плюс `framer-motion`, `react-markdown`, `recharts` (графики в постах)

## Команды

```bash
npm run dev       # локальный сервер
npm run build     # vite build + scripts/generate-blog-pages.mjs
npm run test      # vitest
npm run lint
```

## Роуты

`/` · `/blog` · `/blog/psy/:slug` · `/blog/sal/:slug` · `/blog/:id` · `/module/:id` · `/reviews` · `/privacy` · `/mariyalozovaya` · `/arturgolubev`

Обрати внимание: у постов **категория входит в URL** — `/blog/psy/...` и `/blog/sal/...`.

## Блог

**Данные:** `src/data/blogData.ts` — массив `blogPosts` (~500 КБ, 75 постов). Читай частями через `offset`/`limit`.

```ts
export interface BlogPost {
  id: string;                    // 'psy-N' или 'sal-N', сквозная нумерация внутри категории
  slug: string;                  // транслит запроса, kebab-case
  category: 'psychology' | 'sales';
  title: string;
  excerpt: string;               // 2-3 предложения
  content: string;               // 700-900 слов
  date: string;                  // YYYY-MM-DD
  readTime: string;              // 'N мин'
  image?: string;
  chartData: Record<string, string | number>[];  // 5-7 точек, ключи кириллицей
  chartType: 'bar' | 'line' | 'area';
  chartTitle: string;
  relatedIds: string[];          // 3 id других постов
}
```

**Новый пост добавляется ПОСЛЕДНИМ элементом массива** (перед закрывающей `]`) — в отличие от консалтинга, где первым.

**id:** берётся максимальный существующий в категории и увеличивается на 1 (`psy-42` → `psy-43`).

**График обязателен.** У каждого поста свой `chartData` — это не декор, он рендерится через `recharts` на странице поста. 5-7 точек, ключи метрик по-русски: `[{ name: 'Контроль', влияние: 12 }, ...]`.

### Модули курса — к ним привязывается тема

**Психология:** Когнитивные искажения · Эмоциональный интеллект · Психология влияния · Нейробиология привычек · Управление стрессом · Поведенческая экономика · Психология мотивации · Нейромаркетинг

**Продажи:** Система SPIN-продаж · Построение воронки · Работа с возражениями · Холодные продажи · Социальные продажи · Переговоры и закрытие · Продажи через ценность · Аналитика продаж

Пост должен опираться на релевантный модуль и упоминать знания из него.

### Правила текста — жёсткие, «чтобы не выглядело как ИИ»

- Объём **700-900 слов**. Пиши как живой эксперт-практик.
- **Длинное тире (—) запрещено** везде: `content`, `title`, `excerpt`. Только дефис (-).
- **Запрещённые клише и ИИ-маркеры:** «в современном мире», «в наши дни», «не секрет, что», «важно понимать», «важно отметить», «стоит отметить», «в этой статье мы рассмотрим», «давайте разберёмся», «в заключение», «подводя итог», «таким образом», «в конечном счёте».
- Не начинай абзацы одинаково. Не строй симметричные перечисления. **Максимум один короткий список на статью**, и только если он реально нужен.
- Конкретные примеры, реальные цифры и исследования, разная длина предложений, где уместно — лёгкая разговорность.
- Ключевой запрос входит в заголовок и первый абзац естественно, без переспама.
- Никаких мета-фраз про «эту статью / этот пост / блог».

### Что обновляется вместе с постом
1. `src/data/blogData.ts` — сам пост
2. `public/sitemap.xml` — `<url><loc>https://psytix.ru/blog/{psy|sal}/SLUG</loc>...` перед `</urlset>`, `priority 0.6`

Пункт 2 больше не обязателен: `sitemap.xml` в `dist/` собирается на билде из `blogData.ts` и `courses.ts` (см. «Статика и SEO»). Файл в `public/` остался только чтобы не ломать скрипт автопубликации — его содержимое всё равно перезаписывается.

Коммит: `Блог: [название поста]`, затем `git push origin main` (скрипт psytix пушит изнутри промпта, в отличие от консалтинга).

## Статика и SEO

`scripts/generate-static-pages.mjs` (запускается из `npm run build` после `vite build`) собирает из `dist/index.html` статические страницы для **всех** маршрутов SPA: `/`, `/blog`, `/reviews`, `/mariyalozovaya`, `/arturgolubev`, `/privacy`, 16 `/module/:id` и 75 постов.

Зачем: GitHub Pages отдаёт неизвестный путь как `404.html` со **статусом 404** — SPA-редирект внутри него работает для человека, но такие URL не индексируются. Реальный `index.html` в каталоге маршрута решает это.

Что кладётся в каждую страницу: `<title>`, `description`, OG/Twitter, `rel=canonical`, JSON-LD (Article / Course / FAQPage / BreadcrumbList / Organization / WebSite / Blog / Person) и текст страницы внутри `#root` — бот видит контент без выполнения JS, React перерисовывает его при гидратации.

Там же генерируется `dist/sitemap.xml` — только индексируемые адреса (`/privacy` под `noindex` не попадает), `lastmod` постов берётся из их `date`.

**Новый маршрут в `App.tsx` → добавь его в `staticRoutes` этого скрипта**, иначе страница уедет в 404 для поисковиков.

## Автопубликация

**График: пн/ср/пт в 07:00 МСК, по одному посту в психологию и в продажи.**

Основной механизм - **расписание Claude Code** (Routine) в аккаунте, cron `0 4 * * 1,3,5` UTC. Оно будит сессию с подключённым репозиторием; Claude пишет два поста по правилам из раздела «Блог» и прогоняет их через `scripts/add-post.mjs`. Работает по подписке, **API-ключ не нужен**. Расписание: `trig_019GTRQ2hcuLiDr8rWioQKFv`, привязано к сессии `session_01KMCwJuz3r2qxkRFumZoE35`; посмотреть, поставить на паузу или поменять время - в разделе Routines на claude.ai. Так же устроена выкладка блога golubev-consulting.ru (пн/ср/пт 06:00 МСК).

Предыдущая версия крутилась на ноутбуке через cron и умерла вместе с ним 27 августа 2026: скрипты и контент-планы не сохранились, простой затянулся до 12 октября. Отсюда правило: **расписание не возвращать на локальную машину.**

Запасной путь - `.github/workflows/publish.yml`, только ручной запуск: текст пишет API, нужен секрет `ANTHROPIC_API_KEY`. Устроен так:

**Что делает запасной workflow** для каждой категории по очереди:
1. `node scripts/publish-post.mjs psy|sal` - берёт тему и пишет пост;
2. `npm run build` - пост не уходит в репозиторий, пока сайт с ним не собрался;
3. коммит `Блог: <заголовок>`;
4. после обеих категорий - один пуш в `main` с ретраями;
5. вызывает `deploy.yml` через `workflow_call`. Это обязательно: пуш, сделанный `GITHUB_TOKEN`, сам по себе не запускает другие workflow, поэтому по `on: push` деплой бы не сработал.

Если генерация или сборка упала - изменения откатываются, вторая категория всё равно пробуется, workflow падает с понятной ошибкой в логе.

**Два способа опубликовать пост.**

1. `scripts/add-post.mjs` - **без API и без ключа**. Текст пишет тот, кто запускает скрипт (человек или Claude в сессии), скрипт делает механическую часть: проверки правил, id, слаг, дату, время чтения, связанные посты, вставку в `blogData.ts`, сдвиг счётчика плана. Это путь по подписке, за него ничего не списывается сверх неё.

   ```bash
   node scripts/add-post.mjs psy post.json
   ```

2. `scripts/publish-post.mjs` - полностью автономно, текст генерирует API. Нужен секрет `ANTHROPIC_API_KEY` в настройках репозитория; без него workflow останавливается на первом шаге. Токены тарифицируются отдельно от подписки: в GitHub Actions нет залогиненного CLI, достучаться до модели оттуда можно только по ключу.

Оба пути используют общие чистые функции из `scripts/post-utils.mjs`, так что правила и формат записи у них одинаковые.

**Контент-план:** `content-plan/psy.txt` и `content-plan/sal.txt` - по одной теме в строке; `content-plan/state.json` хранит индекс следующей темы и коммитится вместе с постом. Когда темы кончаются, скрипт выходит с кодом 2 и в логе появляется «контент-план исчерпан» - допишите новые НЧ-запросы в конец файла.

**Что генерирует модель, а что считается кодом.** Модель (`claude-opus-5`, structured output по JSON Schema) отдаёт только `title`, `excerpt`, `content`, `chartTitle`, `chartType`, `chartMetric`, `chartPoints`. Всё остальное детерминированно: `id` - максимальный в категории плюс один, `slug` - транслит темы с защитой от дублей, `date` - по Москве, `readTime` - из объёма, `relatedIds` - три последних поста категории.

**Правила текста** заданы в `SYSTEM_PROMPT` внутри `scripts/publish-post.mjs` и продублированы проверками в `scripts/post-utils.mjs`: объём, длинное тире, запрещённые обороты, 5-7 точек на графике. Пост, не прошедший проверку, не публикуется. Меняете правила - меняйте оба места.

Чистые функции вынесены в `scripts/post-utils.mjs` и покрыты тестами `src/test/publishPost.test.ts` (22 проверки: разбор данных, слаги, экранирование, вставка в массив).

## Telegram

⚠️ **Здесь схема отличается от консалтинга и это проблема.**

`src/lib/telegram.ts` содержит **захардкоженные `TG_BOT_TOKEN` и `TG_CHAT_ID`** и дёргает `api.telegram.org` напрямую из браузера (GET + `mode: 'no-cors'`, fire-and-forget).

Два следствия:

1. **Токен бота попадает в клиентский бандл** и публично доступен любому посетителю сайта. Любой может читать и слать сообщения от имени этого бота. Это стоит починить — перенести отправку на серверный прокси, как сделано в консалтинге (`api.golubev-consulting.ru/lead` → `client-api/server.js`), и отозвать текущий токен через @BotFather.
2. **У посетителей из РФ заявки могут не доходить** — `api.telegram.org` заблокирован, а `no-cors` глушит ошибку, так что сбой не виден ни пользователю, ни в логах.

Пока не переписано — не трогай `sendLeadToTelegram` «по мелочи» и **не копируй токен** в другие файлы, коммиты и сообщения.

3. **Длинная заявка может не дойти.** Текст уезжает в query-строку GET-запроса: ответы квиза + рекомендации дают URL в десятки килобайт, при том что лимит сообщения Telegram — 4096 символов. Лечится тем же прокси (POST с телом). Поведение зафиксировано тестом `src/test/telegram.test.ts`.

**Валидация заявок.** `src/lib/leadContact.ts` — `hasContact()` + `NO_CONTACT_MESSAGE`. Каждая форма перед отправкой проверяет, что заполнено хотя бы одно контактное поле (email / телефон / мессенджер), иначе показывает toast и не шлёт заявку: лид без контакта бесполезен. Все контактные поля по-прежнему необязательные по отдельности — важно, чтобы было заполнено любое.

Формы, использующие `sendLeadToTelegram`: `ValueCalculator`, `QuizTest`, `AIChatAssistant`, `Footer`, `Specialist`, `Golubev`, `ModulePage`, `BlogPostModal` (сейчас нигде не подключён), `BlogPost`. Отправка каждой из них покрыта тестами: `src/test/leadForms.test.tsx`, `src/test/pageForms.test.tsx`.

Поля лида: `name`, `email`, `phone?`, `interest?`, `comment?`, `page`, `button`, `quizAnswers?`, `recommendations?`, `messenger?`, `messengerContact?`. Сообщение форматируется в HTML, время — по `Europe/Moscow`.
